# Core Web Vitals

코어 웹 바이탈은 웹사이트가 검색 엔진 결과에 표시되는 위치에 영향을 미치는 세가지 웹성능 측정값  
**사이트의 전반적인 로딩속도, 상호작용, 웹페이지의 시각적 안정성, 보안 문제** 등 여러요소를 포함

- 페이지 로딩 성능
- 상호작용의 용이성
- 사용자 관점에서 본 페이지의 시각적 안정성

# Core Web Vitals 측정 항목

## LCP(Largest Contentful Paint)

웹 페이지의 로딩 속도에 대한 지표로 콘텐츠 렌더링 시간을 의미  
웹 페이지가 완전히 로드되는 데 걸리는 시간을 측정하는 것이 아니라, 가장 중요한 부붐이 로드되는 시점에만 집중. 즉, 뷰포트내에서 가장 큰 페이지 요소(큰 텍스트 블록, 이미지 또는 비디오)를 표시하는 데 걸리는 시간을 측정

## FID(First Input Delay)

사이트의 상호작용성과 반응성에 대한 사용자의 첫인상을 결정한다.  
사용자가 웹 페이지와 상호작용을 시도하는 첫 번째 순간부터 웹페이지가 응답하는 시간을 측정하기 때문이다. 즉, 브라우저에서 다음 액션이 발생되는 시간까지의 길이를 측정한 지표, 밀리세컨즈(ms)로 측정한다.  
이떄 FID가 중요하게 여기는 요소는 요청받은 액션을 처리하는데 걸리는 시간이 아닌, 입력 지연을 시키는 시간

## CLS(Cumulative Layout Shift)

페이지가 로드될 떄 웹 페이지가 얼마나 안정적인지 측정하고 '시각적 안정성'을 이루고자 한다.  
모바일 중심의 지표. 데스크톱 웹사이트에서는 화면 크기 문제가 대부분 존재하지 않기 때문이다.  
특히 페이지 요소가 화면에서 얼마나 자주 이동하는지 측정. 이로 인해 사용자가 작은 모바일 화면의 콘텐츠와 상호작용 하기 더 어렵다. 화면 요소가 이동하는 일반적인 원인으로는 사용자가 이미 페이지 콘텐츠와 상호작용하고 탐색하기 시작한 후 렌더링되는 광고, 이미지 및 기타 레이아웃 요소가 있다.  
따라서 페이지가 로드될 때 페이지의 요소가 너무 많이 움직인다면 CLS가 높다는 것이므로 개선이 필요합니다.

# Core Web Vitals를 개선하는 가장 효과적인 방법

## 다음 페인트에 대한 상호작용 (INP)

1. 긴 작업을 분할하기 위해 자주 생성
   태스크는 렌더링, 레이아웃, 파싱, 컴파일 또는 스크립트 실행을 비롯하여 브라우저에서 실헹하는 모든 개별 작업. 항상 javascript에서 최대한 적은 작업을 실행하도록 노력해야 하지만 긴 작업을 분할하여 기본 스레드를 도울 수 있다.
2. 불필요한 Javascript 피하기

- 중복된 javascript 기반 구현 대신 널리 사용 가능한 웹 플랫폼 기능인 기준을 사용
- Chrome DevTools의 범위 도구를 사용하여 스크립트에서 사용되지 않는 코드를 찾는다. 시작 중에 필요한 리소스의 크기를 줄이면 페이지에서 코드를 파싱하고 컴파일하는 데 드는 시간을 줄일 수 있으므로 초기 사용자 환경이 더 원할
- 코드 분할을 사용하여 초기 렌더링에는 필요하지 않지만 나중에 사용되는 코드의 별도 번들을 만든다.
- 태그 관리자를 사용하는 경우 주기적으로 태그를 최적화. 사용되지 않는 코드가 있는 이전 태그를 삭제하여 태그 관리자의 javascript 사용량을 줄일 수 있다.

3. 대규모 렌더링 업데이트 방지

- 강제 레이아웃 및 레이아웃 트래싱을 방지하기 위해 javascript 코드에서 DOM 읽기 및 쓰기를 재구성
- DOM 크기를 작게 유지
- CSS 컨테이너 사용: 화면에 표시되지 않는 DOM 콘텐츠를 지연 렌더링. 항상 간단하지 않지만 복잡한 레이아웃이 포함된 영역을 격리하면 불필요한 레이아웃 및 렌더링 작업을 방지

## 최대 콘텐츠 렌더링 시간 (LCP)

1. LCP 리소스가 HTML 소스에서 검색 가능하고 우선순위가 지정되었는지 확인
   LCP 요소가 이미지인 경우 리소스 로드 지연을 줄이려면 HTML 응답에서 이미지의 URL을 검색 가능

- `src` 또는 `srcset` 속성이 있는 `<img>` 요소를 사용하여 이미지를 로드. 렌더링하는 데 javascript가 필요한 `data-src` 와 같은 비표준 속성을 사용 금지. 속도가 항상 느려진다.
- 클라이언트 측 렌더링(CSR)보다 서버 측 렌더링(SSR)을 사용하는 것이 좋다.  
  SSR은 이미지를 포함한 전체 페이지 마크업이 HTML소스에 있음을 의미  
  CSR 솔루션은 이미지를 검색하기 전에 javascript를 실행
- 외부 CSS 또는 JS 파일에서 이미지를 참조해야 하는 경우에도 `<link rel="preload">` 태그를 사용하여 HTML소스에 이미지를 포함할 수 있다. 인라인 스타일에서 참조하는 이미지는 브라우저의 미리 로드 스캐너에서 검색할 수 없으므로 HTML 소스에서 발견되더라고 다른 리소스를 로드할 때 이미지 검색이 차단될 수 있다. 이 경우 미리 로드하면 도움이 된다.

또한 LCP 리소스가 일찍 그리고 높은 우선순위로 로드되도록 하여 리소스의 로드 시간을 단축

- LCP 이미지의 `<img>` 또는 `<link rel="preload">` 태그에 `fetchpriority="high"` 속성을 추가
- LCP 이미지의 `<img>` 태그에서 `loading="lazy"` 속성을 삭제
- 가능한 경우 중요하지 않는 리소스는 연기한다.
