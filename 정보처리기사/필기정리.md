## 1과목: 소프트웨어 설계

### 005. 애자일(Agile) 개발 4가지 핵심 가치

- 프로세스와 도구보다는 개인과 상호작용에 더 가치를 둔다.
- 방대한 문서보다는 실행되는 SW에 더 가치를 둔다.
- 계약 협상보다는 고객과 협업에 더 가치를 둔다.
- 계획을 따르기 보다는 변화에 반응하는 것에 더 가치를 둔다.
  > **XP(eXtreme Programming)의 5가지 핵심 가치:** 의사소통, 단순성, 용기, 존중, 피드백

### 008. 요구사항 개발 프로세스 순서

- **도출(Elicitation)** $\rightarrow$ **분석(Analysis)** $\rightarrow$ **명세(Specification)** $\rightarrow$ **확인(Validation)**

### 011. 자료 사전(DD) 표기 기호

- `=`: 정의
- `+`: 연결
- `( )`: 생략
- `[ ]`: 선택
- `{ }`: 반복
- `* *`: 설명

### 013. UML 구성 요소 및 다이어그램 종류

- **UML 3대 구성 요소:** 사물(Things), 관계(Relationships), 다이어그램(Diagram)
- **구조적(정적) 다이어그램:** 클래스, 객체, 컴포넌트, 배치, 복합체 구조, 패키지 다이어그램
- **행위(동적) 다이어그램 [필수]:** 유스케이스, 순차(Sequence), 커뮤니케이션, 상태, 활동, 상호작용 개요, 타이밍 다이어그램
- **스테레오 타입(`<< >>`):** UML의 기본 기능 외에 추가적인 기능을 표현하기 위해 사용하며, 길러멧(Guilemet)이라고 부르는 겹화살괄호 사이에 형태를 기술함.

### 022. UI(사용자 인터페이스) 기본 원칙

- **직관성:** 누구나 쉽게 이해하고 사용할 수 있어야 한다.
- **유효성:** 사용자의 목적을 정확하고 완벽하게 달성해야 한다.
- **학습성:** 누구나 쉽게 배우고 익힐 수 있어야 한다.

### 026. 모듈화와 결합도/응집도

> 좋은 소프트웨어 설계는 **결합도는 줄이고(약하게), 응집도는 높여야(강하게)** 효과적입니다.

- **결합도의 정도(약함 $\rightarrow$ 강함):** 자료 결합도 $\rightarrow$ 스탬프 결합도 $\rightarrow$ 제어 결합도 $\rightarrow$ 외부 결합도 $\rightarrow$ 공통 결합도 $\rightarrow$ 내용 결합도
- **응집도의 정도(약함 $\rightarrow$ 강함):** 우연적 응집도 $\rightarrow$ 논리적 응집도 $\rightarrow$ 시간적 응집도 $\rightarrow$ 절차적 응집도 $\rightarrow$ 교환적 응집도 $\rightarrow$ 순차적 응집도 $\rightarrow$ 기능적 응집도
- **팬인(Fan-In) / 팬아웃(Fan-Out):** 팬인은 어떤 모듈을 제어(호출)하는 모듈의 수이며, 팬아웃은 어떤 모듈에 의해 제어(호출)되는 모듈의 수이다.

### 038. 객체지향 설계 원칙 (SOLID 원칙)

- **단일 책임 원칙(SRP):** 객체는 단 하나의 책임만 가져야 한다는 원칙
- **개방-폐쇄 원칙(OCP):** 기존의 코드를 변경하지 않고 기능을 추가할 수 있도록 설계해야 한다는 원칙
- **리스코프 치환 원칙(LSP):** 자식 클래스는 최소한 자신의 부모 클래스에서 가능한 행위는 수행할 수 있어야 한다는 설계 원칙
- **인터페이스 분리 원칙(ISP):** 자신이 사용하지 않는 인터페이스와 의존 관계를 맺거나 영향을 받지 않아야 한다는 원칙
- **의존 역전 원칙(DIP):** 각 객체들 간의 의존 관계가 성립될 때, 추상성이 낮은 클래스보다 추상성이 높은 클래스와 의존 관계를 맺어야 한다는 원칙

### 049. 디자인 패턴(Design Pattern) 유형

- **생성 패턴:** 추상 팩토리, 빌더, 팩토리 메소드, 프로토타입, 싱글톤
- **구조 패턴:** 어댑터, 브리지, 컴포지트, 데코레이터, 퍼싸드, 플라이웨이트, 프록시
- **행위 패턴:** 책임 연쇄, 커맨드, 인터프리터, 반복자, 중재자, 메멘토(되돌리기 기능), 옵서버, 상태, 전략, 템플릿 메소드, 방문자

## 2과목: 소프트웨어 개발

### 056. 자료 구조의 분류

- **선형 구조:** 배열, 선형 리스트, 스택, 큐, 데크
- **비선형 구조:** 트리, 그래프

### 062. 이진 트리의 운행법 (Tree Traversal)

- **Preorder (전위):** Root $\rightarrow$ Left $\rightarrow$ Right
- **Inorder (중위):** Left $\rightarrow$ Root $\rightarrow$ Right
- **Postorder (후위):** Left $\rightarrow$ Right $\rightarrow$ Root

### 066. 정렬 알고리즘 특성

- **삽입 정렬(Insertion Sort):** 두 번째 값을 첫 번째 값과 비교하여 알맞은 자리에 삽입하고 나머지를 뒤로 이동시킴.
- **버블 정렬(Bubble Sort) [필수]:** 인접한 두 값을 비교하며 자리를 교환. 1회전이 끝나면 맨 끝에 가장 큰 값이 고정됨.
- **선택 정렬(Selection Sort):** 최소값을 찾아 맨 앞의 원소와 교환.

### 080. 애플리케이션 테스트 원칙

- **파레토 법칙:** 소프트웨어 테스트에서 오류의 80%는 전체 모듈의 20% 내에서 발견된다는 법칙.

### 081. 화이트박스 vs 블랙박스 테스트

- **화이트박스 테스트 종류:** 기초 경로 검사, 제어 구조 검사(조건 검사, 루프 검사, 데이터 흐름 검사)
- **블랙박스 테스트 종류:** 동치 분할 검사, 경계값 분석, 원인-효과 그래프 검사, 오류 예측 검사, 비교 검사

### 087. 통합 테스트 (Integration Test)

- **하향식 통합 테스트:** 프로그램의 상위 모듈에서 하위 모듈 방향으로 통합하며, 시험용 가짜 모듈인 **테스트 스텁(Test Stub)**을 사용함.
- **상향식 통합 테스트:** 프로그램의 하위 모듈에서 상위 모듈 방향으로 통합하며, 하위 모듈을 호출하는 도구인 **테스트 드라이버(Test Driver)**를 사용함.

## 3과목: 데이터베이스 구축

### 101. 데이터베이스 설계 단계 순서

- **개념적 설계** (E-R 다이어그램 모델링) $\rightarrow$ **논리적 설계** (DBMS에 맞는 테이블 변환, 정규화 수행) $\rightarrow$ **물리적 설계** (저장 구조 및 액세스 경로 결정)

### 106. 관계 데이터 모델 용어

- **튜플(Tuple):** 릴레이션을 구성하는 각각의 행, 튜플의 수 = **카디널리티(Cardinality)**
- **속성(Attribute):** 데이터베이스를 구성하는 가장 작은 논리적 단위(열), 속성의 수 = **디그리(Degree) = 차수**
- **도메인(Domain):** 하나의 애트리뷰트가 취할 수 있는 같은 타입의 원자값들의 집합

### 110. 키(Key)의 개념과 특성

- **후보키:** 릴레이션을 구성하는 속성들 중에서 튜플을 유일하게 식별하기 위해 사용하는 속성들의 부분집합으로, **유일성과 최소성**을 모두 만족해야 함.
- **기본키:** 후보키 중에서 특별히 주키(Main Key)로 선정된 키로, **중복값과 NULL 값을 가질 수 없음**.
- **슈퍼키:** 한 릴레이션 내에 있는 속성들의 집합으로 구성된 키로, **유일성은 만족시키지만, 최소성은 만족시키지 못함**.

### 115. 무결성 규정

- **개체 무결성:** 기본 테이블의 기본키를 구성하는 어떤 속성도 **Null 값이나 중복값을 가질 수 없다**는 규정
- **참조 무결성:** 외래키 값은 Null이거나 참조 릴레이션의 기본키 값과 동일해야 한다는 규정

### 116. 관계대수 연산자 기호

- $\sigma$ **(Select):** 선택 조건을 만족하는 튜플의 부분집합을 구함
- $\pi$ **(Project):** 속성 리스트에 제시된 속성 값만을 추출
- $\bowtie$ **(Join):** 공통 속성을 중심으로 두 개의 릴레이션을 하나로 합침
- $\div$ **(Division):** 조건에 맞는 속성을 제외한 속성만을 구함

### 125. 정규화(Normalization) 과정

> 앞 글자를 딴 **"도부이결다조"** 순서대로 암기하세요!

1. **비정규 릴레이션**
2. **1NF:** 도메인이 원자값
3. **2NF:** 부분적 함수 종속 제거
4. **3NF:** 이행적 함수 종속 제거
5. **BCNF:** 결정자이면서 후보키가 아닌 것 제거
6. **4NF:** 다치 종속 제거
7. **5NF:** 조인 종속성 이용

### 132. 트랜잭션의 4대 특성 (ACID)

- **Atomicity(원자성):** 연산은 데이터베이스에 모두 반영되도록 완료(Commit)되든지 아니면 전혀 반영되지 않도록 복구(Rollback)되어야 함.
- **Consistency(일관성):** 실행을 성공적으로 완료하면 언제나 일관성 있는 데이터베이스 상태로 변환함.
- **Isolation(독립성):** 둘 이상의 트랜잭션이 동시에 병행 실행되는 경우 다른 트랜잭션의 연산이 끼어들 수 없음.
- **Durability(영속성):** 성공적으로 완료된 트랜잭션의 결과는 시스템이 고장나더라도 영구적으로 반영되어야 함.

## 4과목: 프로그래밍 언어 활용

### 168. 연산자 우선순위

- 단항 연산자(`!`, `~`) $\rightarrow$ 산술 연산자(`*`, `/`, `%` $\rightarrow$ `+`, `-`) $\rightarrow$ 시프트 연산자 $\rightarrow$ 관계 연산자 $\rightarrow$ 비트 연산자 $\rightarrow$ 논리 연산자(`&&` $\rightarrow$ `||`) $\rightarrow$ 삼항 연산자(`?:`) $\rightarrow$ 대입 연산자
  > `++`, `--` 증감연산자의 경우, 변수 앞에 오는 **전치**는 먼저 값을 증감시킨 후 연산에 사용하고, 변수 뒤에 오는 **후치**는 연산에 먼저 사용한 후 값을 증감시킵니다.

### 200. 기억장치의 배치 전략

- **최초 적합(First Fit):** 첫 번째 분할 영역에 배치
- **최적 적합(Best Fit):** 단편화를 가장 작게 남기는 분할 영역에 배치
- **최악 적합(Worst Fit):** 단편화를 가장 많이 남기는 분할 영역에 배치

### 205. 스케줄링 알고리즘 계산형 문제

- **SJF (Shortest Job First):** 실행 시간이 가장 짧은 프로세스에게 먼저 CPU를 할당하는 기법.
- **HRN (Highest Response-ratio Next) 공식:**
  $$\text{우선순위 수치} = \frac{\text{대기 시간} + \text{서비스 시간}}{\text{서비스 시간}}$$
  > **계산 결과값이 가장 큰 값**이 우선순위가 높습니다.

### 207. 인터넷 주소 체계 - IPv4 vs IPv6

- **IPv4:** 8비트씩 4부분, 총 32비트 구성.
- **IPv6 [필수]:** 16비트씩 8부분, 총 128비트로 구성되며 콜론(:)으로 구분함. 주소 체계로는 **유니캐스트, 멀티캐스트, 애니캐스트**가 있음.

## 5과목: 정보시스템 구축 관리

### 230. LOC 기법의 산정 공식

- **노력(인월)** = $\frac{\text{총 LOC}}{\text{1인당 월평균 생산 코드 라인 수}}$ = 개발 기간 $\times$ 투입 인원

### 234. COCOMO의 소프트웨어 개발 유형

- **조직형(Organic Mode):** 기관 내부에서 개발된 중·소규모의 소프트웨어로 5만(50KDSI) 라인 이하의 소프트웨어를 개발하는 유형
- **반분리형(Semi-Detached Mode):** 트랜잭션 처리 시스템이나 운영체제 등 30만(300KDSI) 라인 이하의 소프트웨어를 개발하는 유형
- **내장형(Embedded Mode):** 초대형 규모의 트랜잭션 처리 시스템이나 운영체제 등 30만(300KDSI) 라인 이상의 소프트웨어를 개발하는 유형

### 243. CMMI의 소프트웨어 프로세스 성숙도 5단계

- **초기(Initial) $\rightarrow$ 관리(Managed) $\rightarrow$ 정의(Defined) $\rightarrow$ 정량적 관리(Quantitatively Managed) $\rightarrow$ 최적화(Optimizing)**

### 293. 보안 3대 요소

- **기밀성:** 시스템 내의 정보와 자원은 인가된 사용자에게만 접근이 허용되며, 정보가 전송 중에 노출되더라도 데이터를 읽을 수 없음.
- **무결성:** 시스템 내의 정보는 오직 인가된 사용자만 수정할 수 있음.
- **가용성:** 인가받은 사용자는 언제라도 사용할 수 있음.

### 302. 암호화 알고리즘 분류

- **개인키(대칭키) 암호화:** 동일한 키로 데이터를 암호화하고 복호화함. 알고리즘이 단순해 속도가 빠름.
  - _블록 암호화 방식:_ DES, SEED, AES, ARIA, IDEA
  - _스트림 암호화 방식:_ LFSR, RC4
- **공개키(비대칭키) 암호화:** 데이터를 암호화할 때 사용하는 공개키는 사용자에게 공개하고, 복호화할 때의 비밀키는 관리자가 관리함. 키의 개수는 $2n$개임. 대표적으로 **RSA**가 있음.
